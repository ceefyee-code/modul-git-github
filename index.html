Persiapan dari Nol Mutlak (Belum Pernah Pakai Git)

1 Langkah 1: Cek & Install Git di Komputer

Buka Terminal di VS Code (Ctrl + ~ atau Cmd + J), lalu cek apakah Git sudah terpasang:

🪟 Cara Install Git di Windows:
  1. Buka browser dan kunjungi situs resmi git-scm.com/downloads/win.
  2. Unduh installer 64-bit Git for Windows Setup, lalu buka file .exe tersebut.
  3. Klik tombol Next terus sampai Install (pengaturan bawaannya sudah sangat ideal untuk pemula).
  4. Setelah selesai, tutup dan buka ulang VS Code, lalu ketik git --version di Terminal VS Code untuk memastikan versi Git sudah muncul.
🍎 Cara Install Git di macOS:
  1. Jika saat mengetik git --version muncul pop-up Xcode Command Line Tools, langsung klik tombol Install dan tunggu hingga selesai.
  2. Atau jalankan perintah instalasi resmi Apple di Terminal:

4 Langkah 4: Cara Login Pertama Kali ke GitHub dari VS Code

Anti Gagal Login

Saat pertama kali menjalankan git push atau klik Publish Branch, laptopmu perlu izin akses ke akun GitHub. Pilih salah satu metode berikut:

✨ Metode A: Login Otomatis via Pop-up VS Code (Termudah)
  1. Klik ikon profil akun di pojok kiri bawah VS Code → pilih Sign in to Sync Settings atau Sign in with GitHub.
  2. Browser akan otomatis terbuka → klik tombol hijau Authorize Visual-Studio-Code.
  3. Kembali ke VS Code. Sekarang setiap kali kamu git push, tidak akan diminta password lagi!
🔑 Metode B: Personal Access Token (Jika Diminta Password di Terminal)
  1. GitHub tidak menerima password akun biasa di terminal.
  2. Buka GitHub di browser → klik Foto Profil → Settings → menu paling bawah Developer settings → Personal access tokens → Tokens (classic).
  3. Klik Generate new token (classic) → centang kotak repo → klik Generate token.
  4. Salin kode ghp_xxxx... lalu tempel (paste) saat terminal meminta Password (ketika di-paste hurufnya memang tidak terlihat demi keamanan, langsung tekan Enter).
Bab 01 • Fondasi Utama

Kamus Dasar & Bahasa Visual VS Code

Sebelum ngetik perintah apapun, kenalan dulu sama istilah-istilah wajib biar nggak gagal paham pas baca tutorial atau error.

🕰️

Apa itu Git?

Git adalah "Mesin Waktu" di dalam laptopmu. Dia mencatat setiap perubahan kode yang kamu simpan. Kalau kodenya tiba-tiba rusak, kamu bisa balik ke versi kemarin yang masih aman. Git bekerja offline di laptop.

☁️

Apa itu GitHub?

GitHub adalah "Google Drive-nya Programmer" di internet (cloud). Tempat menyimpan hasil catatan Git tadi secara online supaya nggak hilang kalau laptop rusak, bisa pamer portofolio, dan kerja bareng tim.

📖 Kamus Istilah Wajib (Pakai Analogi Sehari-hari)

🎨 Kamus Huruf & Warna File di VS Code

Pernah lihat nama file di Explorer VS Code tiba-tiba berubah warna jadi hijau atau kuning dan ada huruf kecil di kanannya? Ini artinya:

U
Untracked (Hijau)

File baru banget dibuat dan belum pernah dicatat/dilacak oleh Git sama sekali.

M
Modified (Kuning)

File lama yang sudah ada di Git, tapi barusan kamu edit/ubah isinya.

A
Added (Hijau)

File baru yang sudah masuk ke Staging Area (git add) dan siap di-commit.

D
Deleted (Merah)

File yang tercatat di Git tapi baru saja kamu hapus dari folder proyek.

C
Conflict (Merah)

Ada bentrokan kode di baris yang sama saat menggabungkan branch atau melakukan pull. Harus dipilih dulu mana kode yang mau dipakai.

⚡ Shortcut Wajib di VS Code

• Buka/Tutup Terminal VS Code: tekan Ctrl + ~ (Windows) atau Cmd + J (Mac).
• Buka Panel Git (Source Control): klik ikon cabang bercabang 3 di sidebar kiri paling luar atau tekan Ctrl + Shift + G.

Bab 02 • Upload Proyek Pertama

Upload Proyek Pertama Kali ke GitHub (2 Mode)

Pilih cara yang paling nyaman buatmu: pakai Terminal (CLI) di Mode 1 atau tombol grafis di VS Code (GUI) di Mode 2.

🚑

Kotak P3K: Solusi Error yang Sering Dialami Pemula

fatal: not a git repository

Penyebab: Kamu lupa ketik git init di awal, atau terminalmu salah folder.
Solusi: Jalankan git init dulu sebelum perintah Git lainnya.

Author identity unknown

Penyebab: Git belum kenal siapa pembuat commit-nya.
Solusi: Jalankan ulang Langkah 1 (git config --global user.name & user.email).

error: remote origin already exists

Penyebab: Link origin sudah pernah dimasukkan sebelumnya.
Solusi: Hapus link lama dengan git remote remove origin lalu masukkan ulang link yang benar.

failed to push some refs

Penyebab: Di GitHub sudah ada file (misal kamu terlanjur centang README saat buat repo) yang belum ada di laptop.
Solusi: Tarik dulu isinya dengan git pull origin main --allow-unrelated-histories lalu git push -u origin main.

Diminta Password / Authentication Failed

Penyebab: GitHub tidak lagi menerima password akun biasa di terminal.
Solusi: Login lewat jendela pop-up browser VS Code, atau buat Personal Access Token (PAT) di GitHub (Settings → Developer settings → Tokens classic) lalu tempel token itu sebagai pengganti password.

✨ Cara A: Auto-Publish Langsung dari VS Code

Paling Praktis

Gunakan cara ini kalau kamu belum membuat repositori di web GitHub. VS Code akan otomatis membuatkan repositori baru sekaligus meng-upload semua filemu!

  1. Buka folder proyek di VS Code, lalu klik ikon Source Control di sidebar kiri (Ctrl+Shift+G).
  2. Klik tombol biru Initialize Repository.
  3. Arahkan kursor ke tulisan Changes → klik ikon + (Stage All Changes).
  4. Tulis pesan di kotak Message (misal: first commit) → klik tombol biru Commit.
  5. Klik tombol hijau/biru Publish Branch → pilih Publish to GitHub public repository (atau private). Selesai!

🔗 Cara B: Hubungkan ke Repo yang Sudah Dibuat

Manual Remote

Gunakan cara ini kalau kamu sudah terlanjur membuat repositori kosong di web GitHub dan ingin menghubungkannya lewat klik tombol:

  1. Lakukan langkah 1 sampai 4 di atas (Initialize → klik + → tulis pesan → klik Commit).
  2. Di bagian atas panel Source Control, klik ikon titik tiga ••• (Views and More Actions).
  3. Pilih menu Remote → klik Add Remote...
  4. Tempel URL HTTPS repositori GitHub-mu (https://github.com/user/repo.git) → tekan Enter.
  5. Ketik nama remote: origin → tekan Enter.
  6. Klik tombol biru Publish Branch! Semua file langsung meluncur ke repositori tersebut.
Bab 03 • Alur Kerja Kronologis

Alur Kerja Berurutan: Clone, Pull, Update & Undo

Biar nggak bingung mana yang dijalankan duluan, ikuti urutan kerja yang benar dari pertama kali mengunduh proyek (git clone), menarik update terbaru (git pull), hingga mengunggah perubahanmu (git push).

🗺️ Urutan Siklus Kerja dari Awal sampai Selesai Ulangi Tahap 2 → 3 setiap hari
1. git clone

Unduh proyek dari GitHub ke laptop (cukup 1x di awal).

2. git pull

Tarik update terbaru (wajib sebelum mulai ngoding).

3. add → commit → push

Edit kode di VS Code, simpan, lalu kirim ke GitHub.

4. Undo / Log

Gunakan fitur mesin waktu kalau ada salah edit/typo.

1 Tahap 1: Unduh Proyek dari GitHub ke Laptop (git clone)

Cukup 1x di Awal

Jalankan tahap ini kalau proyeknya sudah ada di GitHub tapi belum ada di laptopmu (misalnya ganti laptop, ambil proyek tim, atau mengunduh ulang repositorimu sendiri). Jangan download file ZIP dari GitHub—gunakan git clone supaya riwayat Git dan koneksi origin otomatis terpasang!

⌨️ Cara A: Lewat Terminal

Buka terminal di folder tujuan (misal Documents), jalankan git clone, lalu masuk ke dalam folder proyek yang baru terunduh:

*(Perintah code . otomatis membuka folder proyek tersebut di jendela VS Code).*

🖱️ Cara B: Klik Tombol di UI VS Code
  1. Buka jendela baru VS Code (tanpa membuka folder apa pun).
  2. Klik tulisan biru Clone Git Repository... di layar Welcome (atau tekan Ctrl/Cmd+Shift+P lalu ketik Git: Clone).
  3. Tempel URL HTTPS repositori GitHub-mu → tekan Enter.
  4. Pilih folder penyimpanan di laptop → klik Open saat muncul pop-up di pojok kanan bawah.

2 Tahap 2: Tarik Update Terbaru Sebelum Mulai Ngoding (pull vs fetch)

Wajib Sebelum Kerja

Setelah folder proyek sudah ada di laptopmu, biasakan selalu menarik update dulu setiap kali mau mulai ngoding! Apalagi kalau kamu kerja bareng teman tim atau sempat mengedit kode dari perangkat lain / web GitHub.

⬇️ git pull (Langsung Sedot & Gabung)

Mengunduh perubahan terbaru dari GitHub sekaligus langsung menggabungkannya ke file di VS Code kamu. Paling sering dipakai sebelum mulai kerja.

🖱️ Versi Klik Tombol VS Code: Buka panel Source Control → klik titik tiga ... → pilih Pull (atau klik ikon panah berputar di pojok kiri bawah status bar).

👀 git fetch (Intip Dulu Tanpa Mengubah File)

Hanya mengecek dan mengunduh info update dari GitHub ke memori Git tanpa menyentuh file yang sedang kamu edit. Aman kalau kamu mau cek ada update apa saja dulu.

🖱️ Versi Klik Tombol VS Code: Buka panel Source Control → klik titik tiga ... → pilih Pull, Push → klik Fetch.

3 Tahap 3: Edit Kode, Simpan & Upload ke GitHub (add → commit → push)

Setelah Selesai Ngoding

Setelah selesai mengedit index.html atau menambah file baru di VS Code, kamu tidak perlu mengulang git clone, git init, ataupun remote add lagi! Cukup bungkus dan kirim perubahanmu lewat salah satu cara berikut:

⌨️ Cara A: Lewat Terminal (Urutan Wajib — Dipisah per Perintah)
Jalankan 1 per 1 dari Atas

Jalankan keempat perintah berikut secara berurutan di Terminal VS Code setiap kali kamu selesai melakukan perubahan kode:

1 Cek File yang Berubah

Fungsi perintah: Melihat daftar file mana saja yang baru dibuat (merah/Untracked), sudah diedit (Modified), atau sudah siap simpan (hijau/Staged) sebelum dikirim ke GitHub.

2 Masukkan ke Keranjang (Staging Area)

Fungsi perintah: Menandai file yang berubah agar masuk ruang tunggu (Staging). Tanda titik (.) berarti memilih semua file sekaligus (atau ketik git add index.html untuk 1 file saja).

3 Simpan Permanen & Beri Catatan

Fungsi perintah: Membungkus perubahan di Staging menjadi satu titik simpanan permanen (snapshot) di riwayat Git lokal. Flag -m dipakai untuk menulis pesan catatan perubahannya.

4 Upload (Terbangkan) ke GitHub

Fungsi perintah: Mengirim seluruh commit baru dari laptop ke repositori GitHub di internet. Karena dulu sudah pakai -u, sekarang cukup ketik git push saja!

🖱️ Cara B: Klik Tombol di UI VS Code (Tanpa Ketik Kode)
  1. Klik ikon Source Control (ikon cabang di sidebar kiri VS Code, ada angka biru jumlah file berubah).
  2. Arahkan kursor ke tulisan Changes, lalu klik ikon + (Stage All Changes) — ini sama dengan git add ..
  3. Ketik pesan perubahan di kotak Message (misal: fix warna tombol).
  4. Klik tombol biru Commit — ini sama dengan git commit -m "...".
  5. Tombol biru berubah jadi Sync Changes → klik tombol itu untuk langsung git push ke GitHub!

Bab 04 • Fitur Super Git

Kupas Tuntas Materi Branch (Cabang Kerja)

Bayangkan kamu punya website yang sudah jalan bagus di cabang main. Lalu kamu mau bikin fitur baru yang berisiko bikin error. Nah, di sinilah Branch menyelamatkan hidupmu!

🌿

Analogi "Dunia Paralel" (Salinan Draf Aman)

Branch adalah salinan jalur kerja paralel dari kodemu. Saat kamu bikin branch baru bernama fitur-login, kamu bebas mengacak-acak kode di cabang itu. Cabang utama (main) tetap bersih dan aman. Kalau fitur barunya sudah jadi dan sukses, tinggal digabungkan (Merge) ke main!

Simulator Interaktif

Visualisasi Pohon Commit & Posisi HEAD

Status Saat Ini: git status (On branch main)

Kamu sedang berada di cabang main (ditandai lencana kuning HEAD di commit C2). Klik tombol "1. Buat Branch Fitur" untuk mulai bercabang!

🖱️ Panduan Branch Klik Tombol VS Code

Tanpa Terminal
  1. Buat Branch Baru: Lihat pojok kiri paling bawah status bar VS Code (tertulis main), klik nama branch tersebut → pilih + Create new branch... di menu atas → ketik fitur-login → tekan Enter.
  2. Kerjakan Fitur & Commit: Edit file seperti biasa, buka Source Control → klik + → tulis pesan → klik Commit → klik Publish Branch.
  3. Pindah Antar Branch: Klik lagi nama branch di pojok kiri bawah status bar VS Code → pilih main dari daftar menu atas.
  4. Gabungkan (Merge) Branch: Pastikan posisi di pojok kiri bawah sudah main → buka Source Control → klik titik tiga ... → pilih Branch → klik Merge Branch... → pilih fitur-login → klik Sync Changes.
  5. Hapus Branch Selesai: Klik titik tiga ... → Branch → Delete Branch... → pilih fitur-login.

⚡ Gimana Kalau Terjadi Merge Conflict di VS Code? (Jangan Panik!)

Conflict terjadi kalau dua cabang mengedit baris kode yang persis sama. VS Code akan otomatis memunculkan tombol pilihan instan di atas baris yang bentrok:

  • Accept Current Change → Pakai kode milikmu yang sekarang (HEAD).
  • Accept Incoming Change → Pakai kode baru yang masuk dari cabang lawan.
  • Accept Both Changes → Simpan kedua-duanya (atas dan bawah).

Setelah klik salah satu tombol di atas, tinggal klik + (Stage) → klik Commit → klik Sync Changes / Push!

Bab 06 • Onlinekan Karyamu

Step-by-Step Publish & Deploy Website Gratis

Kodenya sudah rapi di GitHub? Saatnya bikin website-mu punya link publik yang bisa dibuka lewat HP siapa saja secara gratis!

🐙 Kapan Pilih GitHub Pages?

Web Statis

Cocok kalau proyekmu berisi HTML, CSS, dan JavaScript murni (tanpa proses build Node.js). Langsung aktif dari dalam pengaturan repositori GitHub tanpa perlu daftar akun lain. Link berbentuk: username.github.io/nama-repo.

▲ Kapan Pilih Vercel?

Super Cepat & Modern

Cocok untuk HTML statis maupun framework modern (React, Next.js, Vite, Vue, Tailwind CLI). Punya fitur Preview Link otomatis setiap kali kamu push branch baru! Link berbentuk: nama-proyek.vercel.app.

🚀 Panduan A: Deploy ke GitHub Pages

Syarat Wajib: Di folder utama (root) repositori GitHub-mu harus ada file bernama index.html (huruf kecil semua).
